# V5 完整交付执行规范

2026-10-13｜适用：原 M01–M18 与 P0。现有开发继续，不等待本文分发。目标是 V5 独立采集、计算、不可变保存、冷读和页面同 run；保留 V4，不新增 M19。

## 1. 发任务前：检查五项

- [ ] **目标**：写清本模块尚缺的可运行链及完成条件，保留已经通过的代码；不要只要求“检查一下”或“交一个文件”。
- [ ] **源码**：提供仓库、原分支、已核 commit、实际源码根与运行目标根、最新固定反馈。候选目录与根工作树不能混用。
- [ ] **交付**：完整可运行增量、依赖闭包、必要测试和启动说明，实际提交原 GitHub 分支。无新增缺口时给现有固定 commit 与逐项证据，不制造无意义修改。
- [ ] **验收**：明确原 producer/reader 到实际出口的正例、关键反例、Mac 后续验证范围；安全、身份、时间与 PIT 合同不放宽。
- [ ] **停止条件**：完整交付或有证据的必要阻塞。开发任务不得混写“仅核收／只输出／不提交”；旧轮临时限制应明确结束。

## 2. 执行与并行

1. 原模块 Chat 并行开发各自分支。可以逐个投递，但不等一个答完才发下一个；已结束回复不能称为后台开发。
2. 开发者自行查当前树、分段读大文件并核实际签名、返回结构和身份字段。单路径 404 不等于源码不存在；“还没读取／还没生成”不构成外部阻塞。
3. 模块拥有模块文件；共享 API、前端、registry、调度由 P0 单 writer 合入。其他模块提供完整接入文件或精确 patch，不能因此停止自身独立开发。Mac 装配和现役变更串行执行。
4. 优先补实际断点：M02 独立 collector；M03 行情 producer→原三件→冷读；M14 原 reader→保存结果页面；M18 request/template→经理保存发布。其他模块沿现有明确缺口推进，不重启全模块泛审。
5. 改源码所需的 manifest/capsule/PIN/AST 必须作为同一版本闭包交付。旧版本保留，新版本采用精确新身份；禁止任意 SHA、伪装旧身份或降低验证。

## 3. 收件、测试和失败处理

- **收件门槛**：远端原分支可达固定 commit；文件与依赖清单完整；启动/装配路径明确；测试命令、退出码和剩余缺口齐全。创建 commit 对象不等于更新分支，旧 manifest 不得漏掉新文件。
- **测试门槛**：至少一个调用原 producer/reader 的贯通正例，以及本次风险对应的拒绝测试。字典 READY、AST/callable、py_compile 或旧测试通过不能替代新链验收。
- **集成门槛**：只核改动及受影响接口，不再次泛审已通过且未变的内容。Mac 按固定版本执行必要隔离测试、保存/冷读与 HTTP/DOM；页面身份需对应同一 run/generation。
- **失败分类**：路径/材料、实现/接口、依赖/身份、测试环境、真实数据/时间窗口、权限/工具。返工必须写“具体失败→改动位置→验证命令”，不再发同一段泛泛催促。
- **真实阻塞**：附动作、目标、原始错误及最小下一步。允许正常工具路径内的有针对性恢复；不重复无效调用，不绕过拒绝。缺执行环境可记测试 NOT_RUN，仍交已能完成的源码；必要输入或权限确实缺失则暂停依赖它的步骤，继续独立部分。
- **时间窗口**：现在可完成隔离实现和受控候选验证；自然窗口另收实际触发证据。错过窗口不得补造 captured_at 或冒充自然运行，手动/回放/合成不能升级为当天自然成功。

## 4. 五段开发 prompt

**① 目标**　继续原 Mxx，基于已验版本补齐〈具体缺口链〉，交完整可运行增量和原分支固定 commit。保留已通过部分，不新增架构、Chat 或 M19。旧轮仅核收/只输出/不提交限制已结束。完成交付或准确报告必要阻塞，不停在计划。

**② 基线**　仓库〈repo〉，原分支〈branch〉，已核〈commit〉，实际源码根〈path〉，运行目标根〈path〉，最新反馈〈固定链接〉。先核当前 HEAD 并继承；按真实树读取必要源码，大文件分段；不猜路径、签名、返回结构，不按旧说明退回过期版本。

**③ 实现**　自行完成本缺口所需源码、依赖闭包、launcher、测试与模块内接线。保留 V4、算法、PIT 和安全语义，不交易、不新增权限或凭据；必要升级同步精确新身份并保留旧合法版本。共享 P0 文件交可应用集成件，由 P0 单 writer 合入。

**④ 验证**　验证〈原 producer/reader〉→〈实际出口〉的正例及〈关键拒绝路径〉。提供命令、退出码、PASS/FAIL/NOT_RUN。无执行环境如实标记，不以此替代源码交付；真实采集与 Mac 验证分别记账，合成、回放、手动、自然不可混称。

**⑤ 交付/阻塞**　实际写入原开发分支，读回确认可达 commit，返回完整文件清单、测试证据、启动/接入说明与剩余缺口。HEAD 变化则继承，不 force、不改 main。可自行查到的信息自行补齐；确实阻塞时给具体动作、目标、原始错误和最小解法，不无限重试。

## 5. 对外进度口径

分别报告：代码交付、独立采集、计算、保存/冷读、页面、自然调度、全链验收。每项带版本和证据范围。真实输入/页面数量不代表模块完成，局部自然成功不代表系统每日同 run。

PASS 只覆盖实际运行范围；FAILED 保留原失败；NOT_RUN 只表示该环节未运行；BLOCKED 必须有具体证据。源码 commit、Mac 已安装版本、预览已启用版本分别记录。仅在新增能力、实际失败、必要决策或完成时更新；工具调用、核收和模型设置不作为成果。

复盘证据见 [RETROSPECTIVE.md](RETROSPECTIVE.md)。本规范不替代原模块接口合同，也不要求已通过模块为了遵循流程重新改写或重测。
