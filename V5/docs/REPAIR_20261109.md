## Reproduced defects and limits

1. The M07 exported verifier pointed at a missing restoration directory and
   historical manifest. Original repository code was present elsewhere. The
   existing source adapter is now connected to those exact original bytes.
   After restoring that wiring, eight cutoff/acquired-at counterexamples across
   the two stages exposed lossy time admission; these are now rejected. Four
   captured-at variants were already rejected by the original window check and
   now fail earlier with an explicit precision error. They are not four
   additional historical bypasses.
2. A sparse session list could report lag 0 for an older panel after omitting
   the newer completed trading day. A coverage declaration must now account
   for every civil day and match the session set. Independent exchange/calendar
   admission and temporary closure evidence remain separate requirements.
3. Evening receipts excluded `checked_at` from identity comparison, then used
   that field for time admission. Editing only that local field was accepted.
   The new containment refuses formal preparation instead of inventing an
   independent time authority.
4. The existing retry precision guard rejected fractions longer than six digits,
   but the parser also discarded a six-digit nonzero fraction of a zero UTC
   offset. At the 16:10 boundary, a true cooldown of 1799.999999 seconds could
   be read as 1800 seconds. The subsequent guard rejects that representation;
   it does not change the cooldown threshold or infer a replacement time.
5. The HK observation validator accepted a time one tenth of a microsecond
   after 09:00 after truncating it to 09:00. Parsing now rejects precision loss,
   and the existing bridge hashes and compiles the same capture byte snapshot
   rather than resolving an ambient module named `capture`.
6. The export inventory still described older daily, evening and Top200 bytes.
   Inventory metadata is reconciled with the actual baseline and new code,
   while original and previous declared identities remain available. This is
   source inventory repair, not a production dependency-pin reapproval.

The already integrated 15:40 owner and 16:10/16:40 precision changes are
retained. Before publication, upstream commit 07da0f8 supplied the same retry
zero-offset repair investigated here. Its exact implementation and tests are
retained; this increment contributes only the additional real-entry preflight
regression, without replacing or recounting that upstream source fix.
Real owner/writer, held lock, prior
state, input basis, runtime dependency admission and same-run receipts still
need reconciliation. Two missing old regression reports are historical
evidence gaps; the audited owner code does not read them as runtime inputs.
